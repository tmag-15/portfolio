02

scoper — in active pilot with two contractors

Scoper

AI intake and quoting for trade contractors — diagnosis, parts list, and cost estimate before anyone drives to the site.

A client describes the job to a chat-style AI intake with photos; Scoper returns a trade-identified diagnosis with a confidence rating, severity, parts, and a cost range. The contractor sends the quote in one click. Low-confidence diagnoses automatically widen the estimate buffer; contractor data is isolated at the database level with row-level security.

Since August the work has been hardening it for the pilot. Row-level security now covers the parts catalog and rate-limit tables, uploads require a signed token bound to the contractor, and a database trigger stops contractors from changing their own status or plan. Contractors got password reset and one-tap call and text links on client phone numbers. SMS sits behind a provider abstraction (mock and Twilio), a nightly pg_cron job clears stale rate-limit rows, and the RLS test suites run in CI.

03

live-golf-scoring — shipped PWA · in real-event use

Live Golf
Scoring

A real-time tournament scoring PWA — run for a 16-player Ryder Cup–style tournament and for live score tracking at a charity event of close to 100 players. It now runs two event formats.

A split-collection Firestore architecture — ten collection paths recombined by a single selector, atomic batched writes, optimistic updates — keeps every phone on every fairway consistent in real time. Match play covers four match formats with dormie, all-square, and concession states, USGA handicap allocation, and a Monte Carlo model for live win probabilities.

The second format is four-team net stroke play: the best three of four nets count on every hole, one marker enters scores for the whole group, tournament skins carry the pot over on ties, and the individual leaderboard switches between net and gross. Score saves queue while offline and merge field by field when signal comes back, and the header says "Synced" only after Firestore confirms the write.

drone platform — in development · first milestone shipped, sim-verified

Drone
Autonomy

A safety-critical platform for autonomous drone fleets — built simulation-first, so the entire system runs end to end before a single propeller spins.

TypeScript services and Python drone agents meet over MQTT, and the simulator speaks the exact message contracts real hardware will — the server never knows it's flying a fake. A deterministic risk engine fuses eight weighted sensor signals into a 0–100 score and a bounded set of actions; a ten-state lifecycle FSM and on-drone failsafes handle disconnects and low battery with no server round-trip; every command is written to an append-only event store before it executes. Milestone one — a five-minute automated scenario running end to end with zero errors — is green, and a 41-finding code audit has been driven to zero.

05

golf-sim — CV launch monitor + UE5 renderer · in development

Golf
Simulator

A camera-based golf launch monitor built from scratch — high-speed stereo vision measures the shot, an Unreal Engine 5 world flies it. Both ends of the pipe, one wire contract.

The Python/OpenCV backend runs 2–3 high-speed cameras (120–1000 fps) through a ten-phase pipeline — detection, 2D Kalman tracking, chessboard calibration, sub-frame clock sync, stereo triangulation, 3D tracking, launch-event extraction, least-squares spin estimation — chasing TrackMan-class accuracy. Each shot leaves as versioned JSON over WebSocket into an Unreal Engine 5 frontend that computes ball flight analytically at 120 Hz — gravity, drag, Magnus, deterministic and automation-tested, no engine physics — and renders it under Lumen. Three full audit passes closed; all twelve test modules green.
